Interactive demo: how a robot builds a memory — then answers from it

This is the core idea behind my embodied question-answering work, made tangible — the full pipeline. First the robot explores: object detection and 2D/3D tracking turn its camera views into a 3D scene graph — rooms, objects, and where things were last seen. Only then can it answer questions, by looking things up in that memory instead of guessing. And because exploration also captures images, the robot can answer some questions from a stored camera frame — even about things that were never tracked as objects in the graph. Start with Explore to watch the memory being built, then ask it something.

Scene-Graph ExplorerA robot’s persistent memory of one home

Step 1 — Explore

The grey, dashed dots are things in the home the robot hasn’t seen yet — right now its scene graph is empty. Press Start exploration and watch it drive through the home: detection finds objects, tracking gives each a persistent ID and a 3D position, and every one becomes a node in the graph.

Build the memory — exploration

Before the robot can answer anything, it has to build the memory. It drives through the home with its RGB+depth cameras on — the dotted line behind it is the route it actually takes. Object detection spots things in the feed; 2D/3D tracking follows each object across views and sessions, giving it a persistent ID and a 3D position; and every tracked object becomes a node in the scene graph — watch the graph fill in below as it explores. It also saves the camera frames it captures along the way, stored with the graph for questions the graph alone can’t answer.

Embodied Question Answering

Fauna Robotics · 2026–present
Co-technical leadVision-Language Models3D Scene Graphs2D/3D TrackingQwen3-VL

A humanoid robot that can answer questions about a home — “where did I leave my mug?”, “is the stove off?” — needs more than a camera feed. It needs a memory. As co-technical lead (with a Principal Engineer), coordinating four researchers, I work on the system that builds and maintains that memory: the robot explores the home, and RGB+depth perception — object detection feeding 2D/3D tracking — is rolled up into a 3D scene graph tracking 400+ household objects across sessions. Exploration also stores the camera images captured along the way, indexed by room and time — so the system can answer questions about things that were never tracked as graph objects at all, like whether the stove was left on, by reading the relevant frame.

On top of that representation sits a fine-tuned Qwen3-VL, tuned for fast information retrieval from the scene graph ahead of any heavier cloud-model reasoning — the design point that makes answers both grounded and quick. The system reached 72% accuracy on OpenEQA, the standard benchmark for embodied question answering. The work is carried out in collaboration with an Amazon Scholar.

Teach-the-Robot: Human-Teaching Pipeline for Robot Memory

Fauna Robotics · Architect
System architectMultimodal RegistrationPersistent MemoryHuman-Robot Interaction

Generic object detection knows what a mug is. It doesn’t know which mug is yours. I am the architect of a team-built pipeline that lets a person teach the robot directly — “this is my favorite mug” — and have that knowledge stick.

The hard part is deciding what to register: the system combines human speech, gesture, and current context to determine which object is being taught and what to do next, then writes it into the robot’s persistent memory — the same scene-graph memory the question-answering system reads from, so a taught object can later be found and fetched. (The explorer at the top of this page has a Teach mode that walks through exactly this flow.)

Face Recognition, Shipped to Customers

Amazon Astro · Senior SDE
ShippedOn-Device MLTensorFlow LiteMobile DSPBiometrics

Astro needs to know who it is talking to — and on a home robot, a false identification is not a rounding error, it is a trust failure. I trained and deployed the face-recognition model that shipped to Astro customers, running on-device under tight compute limits (TensorFlow Lite on a mobile DSP).

The deployed model cut false positives 4× from a 1% false-positive-rate baseline while holding high recall — the operating point that matters when the system runs continuously in someone’s living room. Separately, I am a co-inventor on granted US patent US11858143B1 — a distinct system for identifying a user with an autonomous mobile device, not this face-recognition pipeline itself (see Patent below). A companion hands-free face-enrollment flow reached 95% success in internal beta; it was cancelled before shipping, and I describe it as exactly that.

VLM Diagnostics at Org Scale

Amazon Astro · Senior SDE
Org-wide adoptionVLM Fine-TuningRoot-Cause AnalysisQwen3-VL

When a fleet of robots misbehaves, engineers drown in tickets. I built the ML root-cause analysis system that triages Astro production issues: a fine-tuned Qwen3-VL performs automated diagnosis and classifies and routes each issue to the right team.

Accuracy improved from 50% to 90%, and the system now serves the whole Astro organization at 100+ tickets a day, saving an estimated 1,000+ engineering hours a month. After I demoed it to Devices leadership, a new organization was formed to scale the MVP — the clearest signal an internal tool can get.

Spatial Mapping, Visual SLAM & Scene Reconstruction

Astro / Amazon humanoid work · ongoing
Visual SLAMSuperPoint / LightGlueGaussian SplattingReal-to-SimScene-Graph Navigation

A robot’s map is the foundation every other capability stands on. I contribute — on both implementation and evaluation — to Visual SLAM on Astro and Amazon’s humanoid robots: researching and fine-tuning learned keypoint models (SuperPoint, LightGlue) for the SLAM front end, and building the system that feeds 3D-object signals into the SLAM optimizer as extra constraints. The result: fewer localization failures and better optimization on the localization side.

When SLAM itself is unstable, the team’s scene-graph-based global navigation lets the robot move point-to-point through the home using the 3D scene graph instead. In parallel, I work on multi-camera Gaussian Splatting to construct scenes as the base for real-to-sim transfer — turning real homes into simulation environments robots can practice in.
